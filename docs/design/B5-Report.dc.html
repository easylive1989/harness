登入失敗鎖定
✓ 釐清 ✓ 規格 ✓ 實作 4 報告
概觀

登入流程多了一道以帳號 + IP 計數的鎖定關卡

在既有的 IP 限流之後、密碼驗證之前，加了 lockoutGuard。同一帳號從同一 IP 連續失敗 5 次就鎖 15 分鐘，狀態存在 Redis，所以多台機器共用。鎖定時寄一封通知信，24 小時內最多寄一次。

決策與原因
D2計數存在 Redis來自分岔
選擇　既有 Redis，TTL 15 分鐘
捨棄　in-memory Map：重啟會歸零，多台機器不共享
API 有 3 台機器在負載平衡後面；專案已有 redisClient，不需要新增依賴。
D3鎖定期間一律回 429問題 3
選擇　鎖 15 分鐘，期滿自動解除
捨棄　email 重設才解鎖；改要求驗證碼
統一回應不洩漏帳號是否存在（來自你的反問）；自動解除不需要客服介入。
D1以帳號 + IP 計數問題 1
只用帳號計數的話，攻擊者能故意鎖住別人的帳號；只用 IP 計數則已經由 rateLimit 處理。
D4通知信 24 小時一封來自分岔
避免有人故意輸錯，讓對方一直收到信。
鎖定狀態機 Claude 自訂視覺化
正常 登入失敗→ 計數中 1–4 第 5 次失敗→ 鎖定 15 分 TTL 到期→ 正常
「計數中」時登入成功會直接回到「正常」並清除計數；「鎖定」期間任何請求都回 429，不檢查密碼。
限制與風險
Redis 掛掉時放行
選擇 fail-open，避免 Redis 故障導致所有人無法登入；代價是故障期間沒有鎖定保護。
共用 IP 的誤傷
公司 NAT 後的多人共用 IP，但因為以帳號 + IP 計數，影響僅限同一帳號。
後續工作
信中的「不是我」重設連結（分岔中決定延後）
後台手動解鎖介面
鎖定事件的監控指標
